# 闪粉光照连续性验证

基线：`a2955a8`（PR #53）。本次仅修正亚克力闪粉在灯光掠过印刷面侧向时成片突现/消失的问题。

## 原因与修正

亚克力光线只在外部入射方向处于正面时折射。外部光线越过侧向时，内部方向的法线分量会从非正值跳到约 0.74。直接用这个内部方向判断闪粉入射，会使许多颗粒同时从零亮度跳到高光。

现在分别保留两盏灯折射前的入射量，并在每盏灯有界的闪粉反射上施加平滑衰减。两盏灯充分照亮正面时，新公式与旧公式等价。颗粒位置、随机朝向、密度、LOD、遮罩与视角响应不变。没有新增纹理、渲染通道或颗粒采样循环。

细粉、珠光、白边 UV、镭射、基础款与纸张材质的计算路径不变。这是预览尺度的视觉模型，不是实物涂层光度标定。

## 检查

- `npm run check`：lint、99 项单元测试、build。
- 新增单测：两盏灯分别跨过侧向时的连续收敛、0.25°步长变化、上下界、光源独立性、完整入射与旧公式等价。
- 新增生产 WebGL 回归：两段灯位各按 0.5°递进，使用同角度“闪粉开－关”差值排除环境反射变化；检查单像素峰值、变化像素数量、4×4 空间分区均值、重复帧稳定和多个灯位可见度。
- 原有浏览器检查覆盖深色/浅色/彩色底图、细窄遮罩、材质隔离、零强度与总开关、视角变化、桌面/小屏取景、2D PNG 和 JSON 下载。

## 连续帧结果

在 320px / DPR 3 小屏上下文中，用相同生产模型与相同固定视角对比基线及修复版：

| 0.5°相邻灯位 | 基线 | 修复后 |
| --- | ---: | ---: |
| 主灯跨越侧向的最大像素亮度变化（0–255） | 137 | 17 |
| 主灯变化超过 20/255 的像素数峰值 | 2696 | 0 |
| 主灯 4×4 空间分区平均变化峰值 | 8.5655 | 0.4547 |
| 另一盏灯的最大像素亮度变化（0–255） | 41 | 9 |
| 另一盏灯变化超过 20/255 的像素数峰值 | 40 | 0 |

序列分别为 −47°至−30°、25°至42°，以每个相邻帧的闪粉独立差值计算。静止重复帧完全一致。15°默认灯位的可见颗粒像素数和峰值保持一致。基线在同一测试中触发失败，证明测试能够检出原来的突变。

## 真实素材回归

使用从原始 COS 地址取得并记录 SHA-256 的 14 张图片，未替换素材。覆盖默认模板，以及用户指定的 Untitled / 16500 / 鏡舞舞搭配。

360px（DPR 3，减少动态效果）与 960px（DPR 2）下，默认 15°灯位的完整效果、关闭闪粉、单独细粉、单独珠光、色纸、镭射、基础款共 28 组前后对比均逐像素一致。

最终闪粉开关差异超过 5/255 的显示像素：默认模板手机 2745、桌面 16840；用户模板手机 3287、桌面 20302。峰值为 147–154/255。说明此次修复未通过隐藏闪粉或全局降低默认亮度解决问题。

## 限制

浏览器使用桌面 Chromium / SwiftShader 软件 WebGL。手机为尺寸、DPR、触控和减少动态效果设置的模拟；未在实体 iPhone/Android GPU 或 Safari 上测试。有限角度序列不代表所有硬件和所有视角的保证，也不声称消除正常的单颗粒反光变化。
